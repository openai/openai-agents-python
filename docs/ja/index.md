# OpenAI Agents SDK

!!! note "重要なお知らせ"

    Agents SDK は **機能が完成した状態** です。保守、セキュリティ修正、重大なバグ修正、互換性対応は継続しますが、大規模な新機能は予定されていません。新しいエージェントアプリケーションには、マネージド Codex ハーネス上で動作する **[Agents API](https://developers.openai.com/api/docs/guides/agents-api/quickstart)** を推奨します。

    既存のアプリケーションでは、Agents SDK を引き続き使用できます。Agents API がまだサポートしていない機能を必要とする新しいアプリケーションでは、SDK が当面の選択肢となります。

[OpenAI Agents SDK](https://github.com/openai/openai-agents-python) は、アプリケーションコード内でエージェントワークフローを構築するためのオープンソースフレームワークです。[Swarm](https://github.com/openai/swarm/tree/main) を基盤としており、ガードレールと組み込みのトレーシングを備えた軽量なマルチエージェントオーケストレーションを本番アプリケーションで利用できるようにします。

SDK はアプリケーション内でエージェントループを実行し、MCP サーバーのツールを含むモデル呼び出しとツール実行を調整します。セッションは複数の実行にわたって会話コンテキストを保持し、人間による承認を利用すると、アプリケーションはレビューのためにツール実行を一時停止できます。基本コンポーネントは次のとおりです。

-   **エージェント**: 指示とツールを備えた LLM
-   **Agents as tools / ハンドオフ**: エージェントが特定のタスクを他のエージェントに委任できる仕組み
-   **ガードレール**: エージェントの入力と出力を検証できる仕組み

これらの基本コンポーネントを Python と組み合わせて、複数ステップのワークフローを調整できます。組み込みの **トレーシング** により、これらのワークフローを可視化、デバッグ、評価できます。SDK は、低レイテンシーの音声対話向けの [リアルタイムエージェント](realtime/guide.md) と、ファイルやコマンドを扱うための [サンドボックスエージェント](sandbox_agents.md) もサポートしています。

## Agents SDK を使用する理由 {#why-use-the-agents-sdk}

SDK の設計は、次の 2 つの原則に基づいています。

1. 使用する価値がある十分な機能を備えながら、短時間で習得できるように基本コンポーネントを必要最小限に抑えること。
2. そのままでも優れた動作をしつつ、実際の処理を細部までカスタマイズできること。

SDK の主な機能は次のとおりです。

-   **エージェント**: 指示、ツール、ガードレール、ハンドオフ、およびタスクが完了するまで継続する組み込みループを備えたエージェントを構築できます。
-   **サンドボックスエージェント**: 実際の分離されたワークスペース内で専門エージェントを実行できます。サンドボックスエージェントは、マニフェストで定義されたファイル、サンドボックスクライアントの選択、再開可能なサンドボックスセッションをサポートします。
-   **リアルタイムエージェント**: `gpt-realtime-2.1`、自動中断検出、コンテキスト管理、ガードレールなどを備えた強力な音声エージェントを構築できます。
-   **音声エージェント**: 音声テキスト変換、エージェントワークフロー、テキスト音声変換を組み合わせた音声パイプラインを構築できます。
-   **Python ファースト**: 新しい抽象化概念を学ぶことなく、組み込みの言語機能を使用してエージェントをオーケストレーションし、連携させることができます。
-   **Agents as tools / ハンドオフ**: 複数のエージェント間で作業を調整し、委任するための強力な仕組みです。
-   **ガードレール**: 入力検証と安全性チェックをエージェントの実行と並行して行い、チェックに合格しなかった場合は即座に処理を失敗させます。
-   **関数ツール**: 自動スキーマ生成と Pydantic による検証を使用して、任意の Python 関数をツールに変換できます。
-   **MCP サーバーツールの呼び出し**: リモートの MCP ツールを関数ツールとともにエージェントへ公開する組み込み統合です。
-   **セッション**: エージェントループ内で作業コンテキストを維持するための永続的なメモリレイヤーです。
-   **ヒューマンインザループ**: エージェントの実行中に人間が関与するための組み込みの仕組みです。
-   **トレーシング**: ワークフローの可視化、デバッグ、監視を行うための組み込みのトレーシングであり、OpenAI の評価、ファインチューニング、蒸留ツール一式をサポートします。

## Agents SDK と Responses API の選択 {#agents-sdk-or-responses-api}

新しいエージェントアプリケーションでは、[Agents API](https://developers.openai.com/api/docs/guides/agents-api/quickstart) から始めてください。以下の比較は、独自のアプリケーションコード内でエージェントワークフローを実行する必要がある場合に適用されます。

SDK は OpenAI モデルに対してデフォルトで Responses API を使用しますが、モデル呼び出しをより高レベルなランタイムでラップします。

次の場合は Responses API を直接使用します。

-   ループ、ツールのディスパッチ、状態処理を自身で管理したい場合
-   ワークフローの実行時間が短く、主な目的がモデルの応答を返すことである場合

次の場合は Agents SDK を使用します。

-   ターン、ツール実行、ガードレール、ハンドオフ、セッションをランタイムに管理させたい場合
-   エージェントが成果物を生成する、または連携された複数のステップにわたって動作する必要がある場合
-   [サンドボックスエージェント](sandbox_agents.md) を通じて実際のワークスペースまたは再開可能な実行が必要な場合

どちらか一方を全面的に選択する必要はありません。多くのアプリケーションでは、管理されたワークフローに SDK を使用し、より低レベルな処理経路では Responses API を直接呼び出します。

## インストール {#installation}

```bash
pip install openai-agents
```

## Hello world の例 {#hello-world-example}

```python
from agents import Agent, Runner

agent = Agent(name="Assistant", instructions="You are a helpful assistant")

result = Runner.run_sync(agent, "Write a haiku about recursion in programming.")
print(result.final_output)

# Code within the code,
# Functions calling themselves,
# Infinite loop's dance.
```

(_これを実行する場合は、`OPENAI_API_KEY` 環境変数が設定されていることを確認してください_)

```bash
export OPENAI_API_KEY=sk-...
```
